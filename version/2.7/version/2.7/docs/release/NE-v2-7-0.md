# Next.js Engine v2.7.0 — CLI and Generation 2 Stability

> **Status:** Prepared release candidate; not yet published  
> **Release type:** CLI + compatibility/accessibility fix release  
> **Previous stable source baseline:** v2.6.2  
> **Recommended tag:** `Release-v2.7.0`

NE v2.7.0 adds the NE command-line tool to the Generation 2 package stream while retaining the stable v2 runtime. The release also brings the complete verified release catalog into the CLI and improves CustomSelect controlled usage, accessible naming, and localization.

## What changed

- **NE CLI:** Adds the `ne` executable, type/build checks, release-channel discovery, and the safe updater flow to new Generation 2 package snapshots.
- **Complete release catalog:** Enumerates npm versions, GitHub Releases, and package tags. Entries without verified install artifacts remain visible as catalog-only and cannot be installed.
- **CustomSelect:** Adds controlled `value`, direct `onChange(value, option)` callbacks alongside registered handler names, a caller-provided trigger/search label, configurable search placeholder, and configurable empty-results text.
- **Primitive style precedence:** Keeps the tested precedence contract where component defaults do not override explicit Engine props or `style={}`, while required disabled/runtime state remains enforced. The Generation 2 CI already runs the primitive-style precedence smoke test.
- **Package snapshot:** Adds `bin/` to `content.include` so the executable is included in newly built version snapshots. Existing archived package versions remain untouched.

## Package layout and provenance

The stable `2.7.0` snapshot is generated from the exact merged `main-2` commit at `version/2.7/version/2.7`. The source manifest exposes the `ne` executable through `bin/ne.js`; the release builder copies `bin/` using the root `content.include` allowlist, then carries the matching `bin` entry into the archived package manifest. The control file itself is build-time configuration and is not shipped.

Before publication, the release workflow installs the snapshot dependencies, type-checks the archived package, and runs `npm pack --dry-run`. The snapshot's `UPSTREAM.md` records the source branch and full pinned SHA so the published artifact can be traced back to the exact source tree. Existing published version numbers are immutable and are not overwritten by later source commits.

## Verification gates

The source PR must pass the Generation 2 runtime/type-check/build workflow and Chromium, Firefox, and WebKit compatibility workflow. The package snapshot must then be generated on `package/main` from the exact merged `main-2` commit and pass package validation before publishing.

This note is a prepared release description, **not proof that npm or GitHub has published v2.7.0**. Update the status, tag, and final source range only after the release workflow completes successfully.
