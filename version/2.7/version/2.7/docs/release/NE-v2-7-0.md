# Next.js Engine v2.7.0 — NE CLI and Generation 2 Stability

> **Status:** Prepared release candidate; npm publication and GitHub Release are still pending  
> **Package:** `@kastrick/nextjs-engine@2.7.0`  
> **Release type:** Generation 2 CLI + compatibility/accessibility release  
> **Previous stable release:** v2.6.2  
> **Recommended GitHub tag:** `Release-v2.7.0`  
> **Source branch:** `main-2`

NE v2.7.0 introduces the NE command-line interface to the Generation 2 package stream while retaining the v2 runtime. It also expands release discovery, improves CustomSelect's controlled and accessible contract, and tightens terminal diagnostics and primitive style precedence.

## Highlights

- **NE CLI:** Adds the `ne` command for the project dashboard, development server, production build/start, checks, safe cleanup, release updater, channel/version updates, rollback and help.
- **Adaptive terminal output:** Uses terminal-aware banner sizing, visible-width measurement that ignores ANSI escapes, text wrapping, Unicode/ASCII borders, severity colors, and `--no-color` / `NO_COLOR=1` support.
- **Actionable CLI diagnostics:** Adds stable codes `NE1001`–`NE1004` for unknown commands/options and invalid/missing values. Close command/flag matches are suggested but never executed automatically. Node syntax failures can include a source location and code frame as `NE2001` when Node exposes the needed context. Coded failures link directly to the [NE CLI Error Book](../2/ne-cli-error-book.md).
- **Explicit first-release notice:** The CLI identifies itself as new in v2.7.0 and warns that its command contract may change or be removed in a future release. Interactive users can suppress the notice with `-q` / `--quiet`.
- **Complete release catalog:** Enumerates published npm versions, GitHub Releases and repository package tags. Entries without a verified installable package/artifact remain visible as catalog-only and cannot be installed.
- **CustomSelect:** Adds controlled `value`, direct `onChange(value, option)` callbacks alongside registered handler names, a caller-provided trigger/search label, configurable search placeholder and configurable empty-results text.
- **Primitive style precedence:** Keeps component defaults below explicit Engine props and `style={}`, while preserving required disabled/runtime state.
- **Package snapshot:** Includes `bin/` in new Generation 2 package snapshots and declares the `ne` executable in the package manifest. Existing archived versions are not rewritten.

## Installing the NE CLI

The published package exposes `ne` through npm's `bin` metadata and the Node shebang in `bin/ne.js`:

```sh
npm install --global @kastrick/nextjs-engine
ne --help
ne build
```

npm creates the platform-specific executable link/shim during installation. On POSIX systems it links the executable into the npm global binary directory; on Windows it creates a `.cmd` shim. PowerShell can run `ne` after the npm global binary directory is on `PATH`; no separate hand-maintained `.ps1` or `.sh` launcher is needed.

For a one-shot use without a global installation:

```sh
npx --yes --package=@kastrick/nextjs-engine ne updater
```

The interactive terminal is experimental; the headless commands are the dependable interface for scripts and CI.

## CLI diagnostics and migration references

The Generation 2 CLI's authoritative codes are documented in [NE CLI Error Book](../2/ne-cli-error-book.md). The error output includes a code-specific Help link for recognized `NE####` diagnostics.

Generation 3 has a separate compiler and migration diagnostic namespace. v2.7.0 does not silently convert a Generation 2 project into Generation 3. The verified current migration cases are summarized in [Migrating to Generation 3](../2/migrating-to-3.md), with the full source guide on the `main-3` branch.

The documented Gen 3 migration findings include:

- `RawComponentRenderer` and schema nodes with `type: "raw"` are not supported Gen 3 public APIs; replace them with registered components or normal JSX.
- EngineAPI keeps `.EngineAPIConfig/*.api` as source, but Gen 3's generated config path is `.nextjs-engine/config/.apiconfig.json`; the old root `.engine-api-compiled.json` output is retired.
- `compiler.serverFirst: false` selects the legacy Gen 2 client-renderer compatibility path. It remains a deliberate migration escape hatch, not a recommended default.
- Named handlers in `createPage()` use the Gen 3 provider compatibility path. This is not a removed API, but it is not the normal server-first execution path.

These are the migration rules that the current Gen 3 development diagnostics explicitly detect, not a claim that every unlisted Generation 2 API is unsupported. Review the current Gen 3 documentation and tests before changing an application.

## Package layout and provenance

The stable `2.7.0` snapshot is stored at `version/2.7/version/2.7` on `package/main`. The source manifest maps `ne` to `./bin/ne.js`; the root `content.include` allowlist copies `bin/` into newly generated Generation 2 snapshots. The `content.include` control file is build-time configuration and is not shipped.

The package workflow pins the exact `main-2` source commit, records it in the snapshot's `UPSTREAM.md`, type-checks the archived package, and runs `npm pack --dry-run` before the npm publish step. Published npm versions are immutable; an existing published version must never be overwritten.

- CodeQL.

The versioned `2.7.0` archive snapshot was generated on `package/main`; its package type-check and `npm pack --dry-run` passed. The subsequent npm publish step returned `ENEEDAUTH`, so **v2.7.0 is not yet published to npm**. The GitHub Release tag `Release-v2.7.0` has not yet been created.

The package workflow uses npm Trusted Publishing (OIDC). Before retrying the publish, the package's npm Trusted Publisher must match the GitHub repository and workflow exactly and allow both `npm publish` and `npm dist-tag`. See [npm Trusted Publishing](https://docs.npmjs.com/trusted-publishers/).

After npm publication succeeds, create the GitHub Release from `main-2` using tag `Release-v2.7.0` and these notes. Do not mark this document or the release index as published until npm and GitHub both confirm their respective release steps.
